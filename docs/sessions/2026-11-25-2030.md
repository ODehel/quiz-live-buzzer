## Leçons de méthode
- **Écrire le code d'un bloc après une série de tests perd le rouge individuel** : pour le login d'ouverture, 22 tests ont été écrits avant tout code et le vert est venu d'un seul pas ; la mutation a servi de filet (3 survivants rattrapés). Pour le renouvellement, un stub vide de `SendAuthRefresh` a donné 11 vrais rouges : à refaire pour toute la session suivante (stub, puis rouge, puis vert).
- **Un survivant de mutation est souvent un test qui mesure le mauvais instant** : le test de débordement du compteur ne passait que parce que les deux termes débordaient ensemble ; il fallait interroger **avant** la bascule.
- **Un changement d'interface réécrit des tests « gardés »** : CA-6 et ses tests devaient rester intacts ; l'interface a dû changer (login asynchrone), donc leur arrangement a suivi. À signaler plutôt qu'à découvrir en revue (voir la décision #80).
- **Honnêteté sur le compilé** : `src/` n'avait jamais été compilé pour l'`esp32` à la rédaction du code ; le contrôle contre des stubs ne valait pas un `pio run`. Le smoke test ci-dessous l'a depuis compilé et flashé sur la CrowPanel (voir « Smoke test constaté »).

## Smoke test constaté (2026-11-25, 21:12 à 21:22)

- **Constaté** : `pio run -e esp32` et le flash réussissent (`TaskAsyncLogin`, `ArduinoClock` et `main.cpp` compilés pour l'`esp32` et exécutés sur le matériel). Deux logins au démarrage, `auth` avec le token du second ; login muet abandonné à 4,7 s (limite 5 s, marge de mesure 1,5 s), `auth` avec le dernier token ; pongs aux pings du proxy pendant les logins d'ouverture et de renouvellement ; un seul login et un seul `auth_refresh` pour une rafale de trois `token_expiring_soon` ; token d'un login terminé après la fermeture gardé pour l'ouverture suivante ; `401` tardif ignoré, puis `401` de la connexion suivante : arrêt (« Connexion refusée ») ; trois reconnexions puis « Hors jeu », login abandonné jeté.
