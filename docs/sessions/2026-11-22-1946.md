## Leçons de méthode
- Une US « Vide » n'est pas forcément à reporter en bloc : ce qui est **décidé** (ici l'écran D6, #33 et #36) se cadre en code dormant, et les options **non décidées** (canal, déclencheur) se chiffrent dans la salve avant d'être reportées. Les quatre recommandations de « reporter » ou de « dormant » n'ont créé aucun conflit avec les CA existants.
- Lire le **corps** de la fonction de bibliothèque appelée, pas son seul en-tête : l'`alloca` en boucle de `LGFXBase::qrcode` (2 541 octets jusqu'à la version 11, 59 700 jusqu'à la 40) est ce qui a fondé la borne de 321 octets du CA-2.
- Recouper une affirmation sur le code avant de l'écrire : « `ScreenPresenter` n'a que `ScreenForLoginRefused()` » était faux (quatre méthodes), corrigé après relecture du fichier.
- Les dettes existantes portent parfois une affirmation devenue fausse (« l'écran de configuration n'est pas maquetté », faux depuis #36) : relire celles qui touchent l'US avant de les compléter.
- Un test vert peut figer un ancien rendu : `LoginOutcomeDisplayTest.ShowsTheRefusalScreenWithoutTopBarWhenTheCredentialsAreRefused` fige l'écran de refus sans bandeau, que US-FW-015 CA-9 remplace ; à dire à l'US qui le touche (constat 5).
- Le plan des CA a été dressé avant la Porte 1 et chaque chiffre recompté sur les fichiers après écriture : aucun écart.
